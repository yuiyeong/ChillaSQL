# ChillaSQL 기획서

Nov 11, 2026 · @Yuiyeong · 마지막 수정 Nov 18, 2026

## 1. 개요

ChillaSQL은 DataGrip을 대신해 혼자 쓰는 PostgreSQL 전용 Mac 데스크톱 클라이언트다. 터널이 필요한 DB는 접속 정보에 터널 명령을 붙여 두면 앱이 연결부터 종료까지 처리한다.

| 항목 | 내용 |
| --- | --- |
| 앱 이름 | ChillaSQL. 명령어와 설정 파일은 줄여서 `chilla`, `chilla.toml` |
| 사용자 | 본인 1명 |
| 실행 환경 | macOS |
| 지원 DB | PostgreSQL |
| 배포 | 로컬 빌드 후 직접 설치 (스토어 배포 없음) |
| 화면 | dark 테마 고정. 기본 창 크기 1512×982(14" MacBook Pro 기본 해상도) |
| 화면 언어 | 기본은 영어. 전역 설정 파일에서 한국어로 바꿀 수 있음. PostgreSQL 오류 메시지, SQL keyword, 설정 파일의 key, 결과 data는 번역하지 않음 |
| 글꼴 | 화면은 macOS system font(영문 SF Pro, 한글 Apple SD Gothic Neo). SQL 에디터와 결과 data는 D2Coding |

**만들지 않는 것**

- PostgreSQL 외 다른 DB 지원
- 팀 공유, 계정, 클라우드 동기화
- 스키마 비교, 마이그레이션 도구, ER 다이어그램
- Windows, Linux 지원
- 명령·파일·테이블을 한곳에서 찾는 창(명령 palette), `postgres://` URL 붙여넣기, 결과 안에서 찾기

## 2. 기술 스택

Tauri + React/TypeScript로 확정했다. 화면은 React로, DB 연결과 터널 관리는 Rust로 나눈다.

| 영역 | 선택 | 고른 이유 |
| --- | --- | --- |
| 앱 껍데기 | Tauri 2 | Electron보다 가볍고 Rust로 DB 연결을 직접 다룰 수 있음 |
| 화면 | React + TypeScript + Vite | 이미 쓰고 있는 스택 |
| 스타일 | Tailwind CSS | 이미 쓰고 있는 스택 |
| 화면 상태 | Zustand | 탭, 접속 상태 같은 전역 상태 관리 |
| SQL 에디터 | CodeMirror 6 + lang-sql | Monaco보다 가볍고 PostgreSQL 문법 지원 |
| SQL 포맷터 | sql-formatter | PostgreSQL 방언 지원, 화면 쪽에서 바로 실행 |
| SQL 파서 | pg\_query (PostgreSQL 실제 파서 기반) | 문장 나누기, 위험 쿼리 판별, 파라미터 인식을 정확하게 처리 |
| 결과 표 | TanStack Table + TanStack Virtual | 가상 스크롤로 보이는 행만 그림 |
| DB 드라이버 | tokio-postgres | 세션 고정, 쿼리 취소, 행 단위 스트리밍을 직접 제어 가능 |
| TLS | rustls | SSL 연결과 서버 인증서 검증. tokio-postgres만으로는 SSL 연결이 안 됨 |
| 비밀번호 저장 | keyring-core + apple-native-keyring-store (macOS 키체인) | OS가 암호화를 담당 |
| 터널 프로세스 | tokio::process | 터널 명령을 자식 프로세스로 실행하고 감시 |
| Lint, formatter | ESLint + Prettier, clippy + rustfmt | 화면과 Rust 양쪽의 코드 스타일과 구조 규칙을 도구로 확인 |
| 설정 파일 | TOML (serde) | 사람이 읽고 고치기 쉬움 |
| 화면 문구 | TypeScript dictionary(`en`, `ko`)와 `t(key)` | library 없이 type으로 `ko`에 빠진 key를 잡음. macOS menu(Rust)도 같은 key로 번역 |
| SQL 글꼴 | D2Coding 1.4.0 표준 build(ligature 없는 판), Regular와 Bold | 한글 폭이 영문의 정확히 2배. OFL-1.1이라 앱에 넣을 수 있음. [공식 release](https://github.com/naver/d2-coding-font/releases)에서 받고 subset하지 않음(Reserved Font Name). CSP가 `'self'`라 앱 안에 넣음 |
| 앱 내부 저장소 | SQLite (rusqlite) | 쿼리 기록, 열려 있던 탭, 최근 프로젝트 보관 |

결과 표는 TanStack 조합으로 시작하고, 6장의 성능 기준을 못 맞추면 canvas 기반 그리드로 교체한다.

## 3. 구조

```
화면 (React)                     Rust 코어                       외부
┌──────────────────┐  command   ┌──────────────────┐
│ 에디터, 결과 표,  │ ─────────▶ │ 세션 관리         │ ──────▶ PostgreSQL
│ 스키마 트리, 탭   │ ◀───────── │ 쿼리 실행         │
└──────────────────┘  Channel   │ 터널 관리         │ ──────▶ 터널 명령 (자식 프로세스)
                    (500행씩)  │ 비밀번호          │ ──────▶ macOS 키체인
                               └──────────────────┘
```

화면은 Rust 코어에 명령을 보내고 결과를 500행씩 나눠 받는다. 터널 명령이 있는 접속이면 터널 관리가 명령을 먼저 실행하고, 세션 관리는 열린 포트로 연결한다. 그 접속의 마지막 세션이 끊기면 터널도 끝낸다.

layer 구성과 의존 규칙은 [구조](architecture.md)에 있다.

## 4. 기능 요구사항

기능은 10개 영역으로 나뉜다. 각 기능이 어느 개발 단계에 들어가는지는 8장에 있다.

### 4.1 접속 관리

| 기능 | 동작 |
| --- | --- |
| 접속 정보 | host, port, database, user, password를 저장. 터널 유무와 관계없이 형식은 하나. 연결 대상을 고쳐 저장하면 그 접속을 쓰는 탭의 세션을 묻지 않고 닫음(다음 실행이 새 세션을 엶). 접속 추가는 이미 있는 이름을 거절 |
| 터널 옵션 | 접속 정보에 터널 명령을 추가할 수 있음. 비워 두면 바로 연결 (4.2) |
| 접속 테스트 | 저장 전에 연결 가능 여부 확인. 터널 명령이 있으면 터널까지 포함해 확인 |
| 접속별 색상 | 창 상단 bar(창 전체 폭), 탭, toolbar의 접속 표시에만 색을 써서 어느 DB인지 구분. 오류, 트랜잭션 같은 상태 표시에는 접속 색을 쓰지 않고 icon과 문장으로 구분. 고를 수 있는 색은 green, yellow, red, blue, purple |
| 탭의 접속 | 탭마다 접속 하나. 탭의 접속은 toolbar에서만 바꾸고, sidebar의 접속 목록은 추가와 수정에만 씀 |
| 읽기 전용 | 접속 단위로 켜고 끔 |
| SSL | `sslmode`로 선택: `disable`(기본값), `require`(암호화만), `verify-full`(서버 인증서와 host 이름까지 확인). `verify-full`은 `sslrootcert`로 신뢰할 CA 파일을 정할 수 있고, 없으면 macOS의 trust store로 확인 |

### 4.2 터널 연결 (선택)

접속 정보에 터널 명령을 넣어 두면 DB에 연결하기 전에 앱이 그 명령을 입력한 그대로 실행한다. Railway CLI든 `ssh -L`이든 상관없다. 예: `railway connect Postgres18 -e staging --tunnel-only -P 25432`

세션 흐름은 (터널 실행) → DB connect → 작업 → DB disconnect → (터널 종료)다. 괄호 부분은 터널 명령이 있을 때만 실행된다.

| 상황 | 동작 |
| --- | --- |
| 터널 명령 없음 | 저장된 host와 port로 바로 연결 |
| 접속 시작 | 터널 명령을 자식 프로세스로 실행하고, 접속 정보의 host:port가 열리면 DB에 연결 |
| 포트가 열리지 않음 | 20초(기본값, 접속별 변경 가능) 안에 열리지 않으면 연결을 중단하고 명령의 오류 출력을 그대로 표시 (예: Railway 로그인 만료) |
| 포트가 이미 열려 있음 | 명령을 실행하지 않고 바로 연결. 앱이 띄우지 않은 터널을 쓰는 중이라고 탭에 표시하고, 이 터널은 앱이 끊지 않음 |
| 여러 탭이 같은 접속 사용 | DB 연결은 탭마다 따로, 터널은 하나를 공유 |
| 접속 종료 | DB disconnect 후 터널 종료. 같은 접속을 쓰는 마지막 탭이 끊길 때 실행 |
| 터널 끊김 | 프로세스 종료를 감지해 명령을 다시 실행하고 재연결. 연속 3회 실패하면 멈추고 오류를 표시 |
| 재연결 후 | 세션이 새로 열리므로 SET 값, 임시 테이블 같은 세션 상태가 초기화됐다고 알림 |
| 트랜잭션 중 끊김 | 조용히 재연결하지 않고 트랜잭션이 유실됐다고 알림 |
| 앱 종료 | 열려 있는 세션을 모두 끊고 앱이 띄운 터널을 종료 |

### 4.3 트랜잭션

| 기능 | 동작 |
| --- | --- |
| 기본 모드 | Auto. 문장마다 자동 커밋 |
| Manual 전환 | 탭 단위로 전환. 첫 문장 실행 시 트랜잭션 시작, Commit과 Rollback 버튼 제공 |
| 탭 = 세션 | 탭마다 전용 DB 연결 1개를 고정. 커넥션 풀을 쓰지 않음 |
| 열린 트랜잭션 표시 | 트랜잭션이 열려 있으면 탭에 경과 시간과 함께 표시하고 toolbar에 실행한 문장 수를 표시. Auto 모드에서 직접 BEGIN을 실행한 경우도 포함 |
| 닫기 전 확인 | 트랜잭션이 열린 상태로 탭 닫기, Auto 전환, 탭의 접속 바꾸기 시 Commit 또는 Rollback 선택. 앱 종료 시에는 트랜잭션이 열린 탭을 보여 주고 모두 Rollback하거나 취소만 고름(Commit하려면 취소하고 탭에서 직접) |
| 오류 후 상태 | 트랜잭션이 실패 상태가 되면 표시하고 Rollback 안내 |

### 4.4 SQL 에디터

| 기능 | 동작 |
| --- | --- |
| Highlighting | PostgreSQL 문법 기준 (`::` 캐스팅, `$$` 블록, JSONB 연산자 포함) |
| Formatting | 단축키로 선택 영역 또는 파일 전체 정렬. 화면 문구는 DataGrip을 따라 "Reformat" |
| 자동완성 | 키워드, 스키마, 테이블, 컬럼, 함수. 쿼리 안의 테이블 별칭 인식 |
| 오류 위치 | DB가 알려준 오류 위치를 에디터에 밑줄로 표시 |
| 탭 | 여러 SQL 파일을 탭으로 열기 |
| 파일 저장 | 프로젝트 디렉토리에 `.sql` 파일로 저장. 연 뒤에 밖에서 바뀐 파일은 덮어쓰기 전에 확인하고, 밖에서 지워진 파일은 확인한 뒤 다시 만듦. 줄 끝이 CRLF인 파일은 CRLF로 저장 |
| 자동 보관 | 저장하지 않은 탭 내용도 앱 내부 저장소에 보관해 재시작 후 복원 |

### 4.5 쿼리 실행

| 기능 | 동작 |
| --- | --- |
| 실행 범위 | 커서가 있는 문장, 선택 영역, 파일 전체. 커서가 문장 밖이면 같은 줄의 앞 문장, 없으면 같은 줄의 뒤 문장을 실행하고, 그것도 없으면 실행하지 않음. 실행될 범위를 에디터에 배경과 왼쪽 선으로 표시하고, 실행 버튼 label도 범위에 맞춰 바뀜(문장 / 선택 영역) |
| 문장 나누기 | pg\_query의 scanner(PostgreSQL의 lexer)로 문장 경계를 판별. `$$` 블록, 문자열, 주석 안의 `;`는 경계로 보지 않음. 문법 오류가 있는 문장도 문장으로 나눔 |
| 여러 문장 실행 | 순서대로 실행하고 오류가 나면 그 문장에서 멈춤. 결과는 문장마다 별도 결과 탭으로 표시 |
| 취소 | 실행 중인 쿼리를 DB 쪽에서 중단 |
| 타임아웃 | 접속별 기본값 설정 |
| 실행 정보 | 소요 시간, 영향받은 행 수 표시 |
| 파라미터 | `:id` 같은 변수에 값을 입력해 실행. pg\_query의 scanner로 `::` 캐스팅과 구분 |
| 실행 계획 | EXPLAIN ANALYZE 결과를 tree로 보기. 가장 오래 걸린 노드를 강조하고 원문도 볼 수 있음 |

### 4.6 결과 표

| 기능 | 동작 |
| --- | --- |
| 나눠 가져오기 | 처음 500행만 가져오고 스크롤하면 이어서 가져옴. 행이 크면 500행이 되기 전에 끊음(4 MiB) |
| 받다 만 결과 | 같은 탭에서 다음 쿼리를 실행하면 남은 결과를 버림. 10분(기본값) 동안 더 가져오지 않으면 자동으로 닫아 DB에 쿼리가 열려 있지 않게 함 |
| 보관 상한 | 탭당 10만 행을 넘으면 앞쪽 행부터 버림. 버려진 구간은 자동으로 다시 조회하지 않고 "다시 실행해야 볼 수 있음"으로 표시. 행은 화면이 보관하고, 어디부터 보관할지는 Rust가 알려 줌 |
| 가상 스크롤 | 화면에 보이는 행만 그림 |
| 타입별 표시 | JSONB 펼쳐보기, timestamptz, 배열, NULL과 빈 문자열 구분, vector 같은 긴 값 줄임 표시. 셀을 고르면 옆 panel에 전체 값을 보여 줌(Shift+Enter) |
| 표 조작 | 컬럼 너비 조절, 화면 내 정렬. 일부만 받은 결과를 정렬하면 받은 행만 정렬됐다고 표시 |
| 복사와 내보내기 | 셀, 행 복사(복사하면 알림). CSV, JSON 내보내기 |
| 셀 편집 | PK가 있는 단일 테이블 결과에서 셀을 고치면 UPDATE로 반영 |

### 4.7 스키마 트리

| 기능 | 동작 |
| --- | --- |
| 탐색 | 활성 탭의 접속에서 스키마, 테이블, 뷰, 컬럼, 인덱스, 제약조건 |
| 지연 로딩 | 펼친 항목만 조회 |

| 빠른 조회 | 테이블을 더블클릭하면 앞부분 행 조회. 트리 항목의 menu에서 앞부분 행 조회, DDL 보기, 이름 복사 |
| DDL 보기 | 테이블 생성문 확인. 복사하거나 새 탭에 열 수 있음 |

### 4.8 안전장치

| 기능 | 동작 |
| --- | --- |
| 읽기 전용 접속 | 세션을 읽기 전용으로 열어 DB가 쓰기를 거부하게 함 |
| 위험 쿼리 확인 | WHERE 없는 UPDATE와 DELETE, DROP, TRUNCATE는 실행 전 확인. Manual 모드면 Commit 전까지 되돌릴 수 있다고, Auto 모드면 되돌릴 수 없다고 알림. 읽기 전용 접속에서는 확인하지 않고 실행해 DB의 거부를 그대로 보여 줌 |
| 환경 색상 | 4.1의 접속별 색상으로 운영과 스테이징 구분. "운영" 같은 환경 구분 항목은 따로 두지 않음 |

| 항목 | 내용 |
| --- | --- |
| 범위 | 실행, Formatting, Commit, Rollback, 탭 이동처럼 ChillaSQL에 있는 기능만 맞춤 |
| 변경 | 전역 설정 파일에서 키를 바꿀 수 있음 (5장) |
| M3의 키 | 실행 Cmd+Enter, 취소 Cmd+F2, 저장 Cmd+S, 새 탭 Shift+Cmd+L, 탭 닫기 Cmd+W, 다음 탭 Shift+Cmd+], 이전 탭 Shift+Cmd+[. 입력 소스와 무관하게 key의 위치로 판별. 접속 form이 열려 있는 동안은 동작하지 않음 |
| M4 이후의 키 | Formatting Opt+Cmd+L, 프로젝트 열기 Cmd+O, 값 보기 Shift+Enter, Commit, Rollback. DataGrip 키맵과 같은지 확인한 뒤 정함(9장) |

## 5. 프로젝트 디렉토리

디렉토리 하나가 프로젝트 하나다. 설정 파일이 있는 디렉토리를 열면 그 안의 접속 목록과 SQL 파일이 프로젝트로 묶인다. 설정 파일이 없는 디렉토리를 열면 앱이 `[project]`만 든 `chilla.toml`을 만들 수 있다. SQL 파일 목록에는 `.`으로 시작하는 이름, `node_modules`, `target`, symlink가 빠지고, 16 MiB를 넘는 파일은 열지 않는다.

```
my-service/
├── chilla.toml        접속 목록과 프로젝트 설정 (비밀 정보 없음)
├── queries/
│   ├── users.sql
│   └── billing/
│       └── refunds.sql
└── scratch.sql
```

chilla.toml 예시:

```toml
[project]
name = "my-service"

# 운영: public IP로 바로 접속 (터널 없음)
[connections.production]
host = "203.0.113.10"
port = 5432
database = "app"
user = "app_user"
sslmode = "require"        # 서버 인증서까지 확인하려면 "verify-full"
# sslrootcert = "certs/ca.pem"   # verify-full에서 이 CA만 신뢰
color = "red"

# 스테이징: 터널 명령을 먼저 실행한 뒤 접속
[connections.staging]
host = "localhost"
port = 25432
database = "railway"
user = "postgres"
tunnel = "railway connect Postgres18 -e staging --tunnel-only -P 25432"
color = "yellow"

[connections.local]
host = "localhost"
port = 5432
database = "app"
user = "postgres"
color = "green"
```

| 저장 위치 | 들어가는 것 |
| --- | --- |
| 프로젝트 디렉토리 | 설정 파일(접속 정보와 터널 명령, 비밀번호 제외), `.sql` 파일. git에 올려도 안전 |
| 전역 설정 파일 `~/.config/chilla/config.toml` | 단축키, 결과 보관 상한, 화면 언어(`language = "en"` 또는 `"ko"`), 에디터 글꼴과 크기처럼 모든 프로젝트에 적용되는 설정 |
| macOS 키체인 | 모든 접속의 비밀번호. 프로젝트 경로와 접속 이름으로 구분하므로 디렉토리를 옮기면 다시 입력 |
| 앱 내부 저장소 (SQLite) | 쿼리 기록, 열려 있던 탭과 저장하지 않은 내용, 최근 프로젝트 목록 |

## 6. 성능 기준

결과가 아무리 커도 화면이 멈추지 않는 것이 기준이다. 아래 수치는 제안한 목표값이며 써 보면서 조정한다.

| 항목 | 목표 | 달성 방법 |
| --- | --- | --- |
| 앱 시작부터 프로젝트 화면까지 | 1초 이내 | 스키마 정보는 접속 후 뒤에서 불러옴 |
| 첫 결과 표시 | DB 응답 후 0.1초 이내 | 처음 500행만 받아 바로 그림 |
| 결과 표 스크롤 | 100만 행 결과에서도 끊김 없음 | 가상 스크롤, 나눠 가져오기 |
| 에디터 입력 | 1만 줄 파일에서도 지연 없음 | CodeMirror의 보이는 영역만 처리 |
| 자동완성 표시 | 0.05초 이내 | 스키마 정보를 메모리에 보관 |
| 쿼리 취소 | 1초 이내 반응 | DB에 취소 요청을 별도 연결로 전송 |
| 메모리 | 탭당 최대 10만 행 보관 (기본값, 설정에서 변경 가능) | 상한을 넘으면 앞쪽 행부터 버림. 자동으로 다시 조회하지 않음 (4.6) |

쿼리 실행은 전부 Rust 쪽 비동기로 처리해 화면 스레드를 막지 않는다.

## 7. 보안

비밀번호는 파일에 쓰지 않고 macOS 키체인에만 둔다. 암호화와 잠금 해제는 OS가 맡으므로 앱이 암호화 키를 따로 관리하지 않는다.

| 대상 | 처리 |
| --- | --- |
| 접속 비밀번호 | 키체인에 저장. 항목은 프로젝트 경로와 접속 이름으로 구분(service `com.yuiyeong.chillasql`, account `<프로젝트 디렉토리 절대 경로>::<접속 이름>`). 설정 파일에는 password 항목 자체가 없고, 있으면 프로젝트를 열지 않음. 접속의 연결 대상(host, port, database, user, SSL 설정, 터널)을 바꿔 저장하면 저장된 비밀번호를 지움. 프로젝트에 없던 이름으로 저장할 때도 남아 있던 비밀번호를 지우며, 지우는 일은 설정 파일을 쓰기 전에 함 |
| 전송 구간 | public IP 접속은 SSL 사용. `require`는 암호화만 하고, `verify-full`은 서버 인증서까지 확인 |
| 터널 명령 | 설정 파일에 평문으로 저장. 명령 안에 토큰이나 비밀번호를 직접 쓰지 않음 |
| 설정 파일 | 비밀 정보가 들어가지 않도록 저장 시 검사 |
| 쿼리 기록 | 앱 내부 저장소에 평문 보관. 쿼리 본문에 비밀 값을 직접 쓰면 기록에 남는다는 점은 감수 |
| 로그 | 접속 문자열과 비밀번호는 로그에 남기지 않음 |
| 화면과 Rust 사이 | 비밀번호는 Rust 쪽에만 두고 화면 쪽으로 넘기지 않음. CSP로 앱 자신의 script만 실행 |

## 8. 개발 단계

4단계로 나누고, 3단계가 끝나면 DataGrip 없이 일할 수 있는 상태가 된다. 각 단계는 끝날 때마다 실제로 써 보고 다음으로 넘어간다.

| 단계 | 들어가는 기능 | 완료 기준 |
| --- | --- | --- |
| 1. 뼈대 | 프로젝트 열기, 터널 없는 접속, SSL, 키체인 저장, 접속 테스트, 에디터와 Highlighting, 문장 나누기(SQL 파서), 커서 문장과 선택 영역 실행, 실행 정보, 결과 표(가상 스크롤, 나눠 가져오기, 보관 상한, 컬럼 너비), 셀과 행 복사, 쿼리 취소, 탭 = 세션 구조, 기본 단축키, 화면 디자인 적용, 영어 화면 문구, D2Coding | 로컬 DB에서 100만 행 결과를 끊김 없이 스크롤 |
| 2. 터널과 트랜잭션 | 터널 명령 실행과 감시, 재연결과 재시도 제한, disconnect 시 터널 종료, Auto와 Manual 전환, 열린 트랜잭션 표시, 닫기 전 확인, 접속별 색상, 위험 쿼리 확인, 받다 만 결과 자동 닫기 | 터미널 없이 Railway staging에 접속해 Manual 트랜잭션을 Commit, Rollback |
| 3. 매일 쓰는 편의 | 스키마 트리, 빠른 조회, 자동완성, Formatting, 타입별 표시, 오류 위치, 읽기 전용, 타임아웃, 파일 전체 실행과 여러 결과 표시, 저장하지 않은 탭 자동 보관, 전역 설정 파일, 한국어 화면 문구와 언어 설정 | 하루 업무를 DataGrip 없이 처리 |
| 4. 나머지 | 쿼리 기록, 셀 편집, 내보내기, EXPLAIN ANALYZE, DDL 보기, 파라미터, 화면 내 정렬, 단축키 변경 | 4장의 모든 기능 동작 |

탭 = 세션 구조는 나중에 바꾸기 어려워서 1단계에 넣었다. 2단계의 Manual 트랜잭션이 이 구조 위에 올라간다. 운영 DB에는 접속별 색상과 위험 쿼리 확인이 들어가는 2단계가 끝난 뒤부터 접속한다.

## 9. 미정 사항

앱 이름, 운영 DB 접속 방식, 터널 대기 시간, 결과 보관 상한은 정해져 각 장에 반영되어 있다.

검토하면서 새로 넣은 기본값 두 개는 써 보면서 조정한다.

- [ ] 받다 만 결과를 자동으로 닫는 시간: 10분
- [ ] 터널 재실행 연속 실패 허용 횟수: 3회

디자인(2026-11-18)에서 남은 것은 괄호 안의 마일스톤에서 정한다.

- [ ] 접속 설정의 key 이름. 디자인은 `tunnel_timeout`(M5), `read_only`와 `statement_timeout`(M8)으로 제안
- [ ] Commit, Rollback(디자인은 Opt+Shift+Cmd+K, Opt+Shift+Cmd+Z), 프로젝트 열기 Cmd+O, 값 보기 Shift+Enter가 DataGrip 키맵과 같은지(M6, M8)
- [ ] 파라미터 값을 SQL text에 그대로 넣을지(M9)
- [ ] 내보내기가 받은 행만 저장하는지, 전체를 다시 조회하는지(M10)
