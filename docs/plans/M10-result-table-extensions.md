# M10 결과 표 확장 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 결과 표에 셀 편집(PK가 있는 단일 테이블 결과를 UPDATE로 반영), 화면 내 정렬, CSV와 JSON 내보내기, 전역 설정 파일의 단축키 변경을 더한다. 완료 기준은 "기획서 4장의 모든 기능 동작"이다.

**Architecture:** Rust는 네 가지를 새로 한다. (1) `TxTap`이 RowDescription에서 이미 읽는 열마다의 table OID와 attnum을 `Column`에 싣는다. (2) catalog connection이 table OID 묶음의 이름, 종류, 컬럼(attnum, PK, 고칠 수 있는지)을 답한다. (3) session actor의 새 명령 `apply_edits`가 화면이 만든 UPDATE 문장들을 한 단위(`BEGIN … COMMIT` 또는 savepoint)로 보내고 문장마다 정확히 한 행이 바뀌었는지 확인한다. (4) 설정 파일의 `[shortcuts]`를 읽고 검사해 완성된 keymap을 화면에 준다. 편집 가능 여부 판단, UPDATE 문 조립, 정렬, CSV/JSON 조립은 화면의 순수 함수다. 파일 쓰기만 Rust command다.

**Tech Stack:** M9의 stack 그대로. 새 package와 crate는 없다. `@tauri-apps/plugin-dialog`의 `save`와 capability `dialog:allow-save`를 더한다.

**Spec:** [기획서](../spec.md) 4.6(표 조작, 복사와 내보내기, 셀 편집), 4.8(읽기 전용 접속), 4.10(단축키 변경), 5장(전역 설정 파일), 9장 / [마일스톤](../milestones.md) M10 / [디자인](../design/README.md)의 `Tools`(M10 셀 편집, 편집할 수 없는 결과와 내보내기 menu), `TabsConn`(4·5·6 결과 표), `Tokens` / [구조](../architecture.md)

## 이 계획에서 정한 것

기획서에 없거나 다르게 정한 것이다. Task 1에서 진행상황의 결정 기록에 옮기고, 기획서와 마일스톤도 고친다.

- **편집할 수 있는 결과.** 표를 그리는 끝난 결과(`finished`이고 outcome이 `completed`, `cancelled`, `expired`)만 편집한다. 행을 받는 중인 결과(`running`)는 편집하지 않는다(Apply가 세션을 쓰려면 열린 결과를 버려야 하고, 버리면 표가 사라진다). 여러 문장의 결과 탭은 지금 보이는 결과를 편집한다. 편집할 수 없는 이유와 문구(Tools M10의 note):
  - 읽기 전용 접속: `Not editable: the connection is read-only.`
  - 받는 중: `Not editable while rows are still coming. Cancel keeps the rows received so far.`
  - 테이블 열이 없음(모두 OID 0): `Not editable: no column comes from a table.`
  - OID가 둘 이상: `Not editable: rows come from {count} tables ({names}).`(이름은 relname, 셋까지 쓰고 그 뒤는 `…`)
  - table이 아님: `Not editable: {name} is not a table.`
  - PK 없음: `Not editable: {name} has no primary key.`
  - PK 컬럼이 결과에 없음: `Not editable: the result does not include the primary key ({columns}).`
  - 테이블이 없어짐: `Not editable: the table no longer exists.`
  - 그 열만: OID 0이면 `Not editable: {column} is computed.`, generated나 `GENERATED ALWAYS` identity면 `Not editable: {column} is generated by the database.`
- **편집 UI(Tools M10).** 편집할 수 있는 셀을 두 번 누르거나, 셀을 고르고 `Enter`를 누르면 그 칸에 editor(textarea, D2Coding 13, 칸 크기)가 열린다. `Enter`는 확정, `Opt+Enter`는 줄바꿈, `Esc`는 취소, 바깥을 누르면 확정이다. 원래 값과 같으면 변경이 아니다. NULL인 셀을 빈 채 확정하면 NULL 그대로다. 셀 우클릭 menu는 `Set NULL`과 `Revert value`(바뀐 셀만). 바뀐 셀은 `inset 2px 0 0 accent`와 `accent/8` 배경이다. 편집할 수 없는 셀을 두 번 누르거나 `Enter`를 누르면 result header 아래에 note(자물쇠 icon, 위 문구)가 뜨고 선택이 바뀌면 사라진다.
- **편집 상태.** 바뀐 값은 탭의 보이는 결과(`runKey`)에 묶이고 키는 (결과 행 번호, attnum)이다. 같은 attnum의 열이 둘이면(`email AS e, email`) 둘 다 바뀐 값을 보인다. 같은 탭의 다음 실행, release, 다른 결과의 편집 시작이 바뀐 값을 묻지 않고 버린다.
- **header와 미리 보기.** 바뀐 셀이 있으면 header에 `{n} cells changed`(`edit.changed.one/other`), Revert(ghost 24px), Apply(primary 24px)가 오고, 표 아래에 `SQL to send on Apply` label과 보낼 SQL(M9 `highlightSql`로 칠한 mono 13 pre, `bg-1`, 최대 높이 160px scroll)이 뜬다.
- **UPDATE 문.** 바뀐 행마다 한 문장, 결과 행 번호 순. `UPDATE {schema.table} SET {col} = {value}[, …] WHERE {pk} = {원래 값}[ AND …] RETURNING {바뀐 col, …};`. SET은 attnum 순. 이름은 서버의 `quote_ident`. 값은 NULL이면 `NULL`, 컬럼 type category가 `N`이고 `^-?\d+$`(정수)면 그대로(처음에는 소수도 `^-?\d+(\.\d+)?$`로 그대로 썼으나 최종 review에서 바꿨다. 소수는 `'1.5'`처럼 따옴표로 감싼다), `\`가 있으면 `E'…'`(`\`와 `'`를 두 번), 그 밖은 `'…'`(`'`를 두 번). type은 쓰지 않는다(unknown literal을 서버가 컬럼 type으로 바꾼다). **`RETURNING`은 캔버스 예시에 없지만 더한다.** 서버가 저장한 text(`2026-11-20` → `2026-11-20 00:00:00+09`)를 표에 다시 그리기 위해서다.
- **Apply.** actor 명령 `apply_edits`가 문장들을 한 단위로 보낸다. 트랜잭션 밖이고 Auto면 `BEGIN` … `COMMIT`(실패하면 `ROLLBACK`), Manual이고 트랜잭션 밖이면 `BEGIN; SAVEPOINT chilla_edit` … `RELEASE SAVEPOINT chilla_edit`(트랜잭션은 열린 채), 트랜잭션 안이면 `SAVEPOINT chilla_edit` … `RELEASE`(실패하면 `ROLLBACK TO SAVEPOINT chilla_edit; RELEASE SAVEPOINT chilla_edit`, 트랜잭션은 열린 채 실패 상태가 되지 않음). 문장마다 행이 정확히 하나여야 하고 아니면 전부 되돌린다. 실패한 트랜잭션에는 보내지 않는다. 확인 dialog는 없다(미리 보기와 Apply 버튼이 확인이다). 성공하면 `RETURNING` 값으로 표의 셀을 바꾸고 바뀐 값을 지우고 toast `Updated {n} rows`. 실패하면 바뀐 값을 두고 note에 이유: 행이 없으면 `Row {row} was not found. It may have been deleted or its key changed. Nothing was applied.`, 서버 오류면 `Row {row}: {message}. Nothing was applied.`(COMMIT 오류면 `{message}. Nothing was applied.`), 실패한 트랜잭션이면 `Roll back the failed transaction first.`. Apply는 그 탭이 실행 중이거나 끝내기를 기다리는 중이면 disabled. 보낸 문장은 줄바꿈으로 이어 쿼리 기록에 한 개로 남긴다. Manual이나 트랜잭션 안의 Apply는 트랜잭션의 문장 수에 문장 수만큼 더한다.
- **정렬.** header의 이름 부분을 누르면 오름차순 → 내림차순 → 정렬 없음. 한 열만. 이름 뒤에 `↑`/`↓`(fg-2), `aria-sort`. 비교는 type category `N`이면 값의 크기(임의 길이 정수와 소수, `-Infinity` < 수 < `Infinity` < `NaN`, 수로 읽을 수 없는 값은 문자열 비교), 그 밖은 UTF-16 code unit 순(`COLLATE "C"`와 같은 순). NULL은 오름차순에서 끝, 내림차순에서 처음(PostgreSQL 기본). 같은 값은 결과 순서를 지킨다. 행 번호 열은 결과의 행 번호를 그대로 보인다. 행 범위 선택(`Shift`+클릭)과 복사는 보이는 순서를 따른다. 정렬한 동안은 스크롤로 다음 batch를 요청하지 않고, 이미 요청한 batch가 오면 정렬에 넣는다. 결과가 일부면(받는 중, `cancelled`, `expired`, 앞 행을 버림) header에 `Sorted {count} received rows only`(fg-2)를 더한다. 정렬은 탭을 바꿨다 와도 이어 간다(`GridView`).
- **내보내기(Tools M10).** 표가 있으면 header 오른쪽, 복사 버튼 앞에 `Export`(ghost 26px)와 menu `Save as CSV…`, `Save as JSON…`. 저장 dialog의 기본 이름은 `result.csv`/`result.json`, 기본 위치는 프로젝트 디렉토리. 받은 행만(앞에서 버린 행 제외), 보이는 순서(정렬 반영), 서버 값(Apply 안 한 변경은 넣지 않음)으로 쓴다. 끝나면 toast `Saved {count} rows to {file}`, 결과가 일부면 `Saved {count} received rows to {file}`. 쓰지 못하면 toast 대신 오류 dialog.
  - CSV: 첫 줄 컬럼 이름, `,`, 줄 끝 LF, UTF-8(BOM 없음). `,` `"` CR LF가 있거나 빈 문자열이면 `"`로 감싸고 `"`는 두 번. NULL은 감싸지 않은 빈 칸. PostgreSQL `COPY … CSV HEADER`와 같은 규칙이다.
  - JSON: object의 배열, 한 줄에 행 하나(`[\n{…},\n{…}\n]`). key는 컬럼 이름이고 같은 이름이 또 나오면 `_2`, `_3`을 붙인다. NULL은 `null`, category `N`이고 JSON 수 문법에 맞으면 수, type 이름이 `boolean`이면 `t`/`f` → `true`/`false`, `json`/`jsonb`면 서버 text를 그대로, 그 밖과 type을 모르는 열은 문자열.
- **단축키 변경.** `config.toml`의 `[shortcuts]`. key는 `run`, `run_file`, `explain`, `cancel`, `save`, `new_tab`, `close_tab`, `next_tab`, `prev_tab`, `commit`, `rollback`, `reformat`, `open_project`. 값은 `"Opt+Shift+Cmd+Enter"` 꼴: modifier `Ctrl`, `Opt`, `Shift`, `Cmd`(순서 무관, 대소문자 무관) 뒤에 key 하나. `Cmd`가 꼭 있어야 한다. key는 `A`–`Z`, `0`–`9`, `F1`–`F12`, `Enter`, `[` `]` `,` `.` `/` `;` `'` `-` `=` `` ` `` `\`. 쓰지 않은 command는 기본값이고 `run_file`, `explain`은 기본값이 없다. 기본값과 합친 뒤 두 command가 같은 키면 오류, app menu의 키(`Cmd+Q`, `Cmd+H`, `Opt+Cmd+H`, `Cmd+M`, `Cmd+C`, `Cmd+V`, `Cmd+X`, `Cmd+A`, `Cmd+Z`, `Shift+Cmd+Z`, `Ctrl+Cmd+F`)도 오류. 오류면 M8 규칙대로 파일 전체를 기본값으로 시작하고 첫 화면에 이유를 보인다. 단축키를 지우는 방법은 두지 않는다. 결과 표의 `Shift+Enter`(값 보기)와 `Enter`(편집)는 표 안의 key라 바꾸지 않는다. 화면의 `⌘` 표시와 `aria-keyshortcuts`는 바꾼 키를 따른다.

## Global Constraints

- 의존 방향: `infrastructure` → `application` → `domain`(`tests/layer_deps.rs`). `tokio-postgres`는 `infrastructure`에만 둔다. `chilla-core`는 `tauri`에 의존하지 않는다.
- `@tauri-apps/*`는 `src/shared/api/`에서만 import한다.
- 화면 문구는 `src/shared/i18n/en.ts`와 `ko.ts`에 함께 더한다. SQL, 결과 data, 컬럼과 테이블 이름, PostgreSQL 오류는 번역하지 않는다. 새 Rust 오류 kind는 `errorKinds.json`과 `error.<kind>` 문구에 더한다.
- 색, 그림자, 글자 크기는 `src/index.css`의 token으로만 쓴다. 미리 보기 SQL 색은 `text-syntax-*`를 다시 쓴다.
- 상수: savepoint 이름 `chilla_edit`, 미리 보기 최대 높이 160px, note의 테이블 이름 최대 3개, 기본 파일 이름 `result.csv`/`result.json`.
- 결과 data는 서버 text 그대로다(`Cell = string | null`). 값을 고칠 때 type으로 바꾸지 않는다.
- commit 전에 `pnpm check`를 통과시킨다. commit message는 `feat:`/`fix:`/`docs:`/`chore:`/`test:` 뒤에 한국어 한 줄이다.
- `docs/`는 평서체, 기술 용어는 영어, 날짜는 `YYYY-MM-DD`, 단축키는 `Cmd+Enter`처럼 글자로 쓴다.

## Review Focus

test가 없으면 사용자가 가장 먼저 부딪힐 입력과 상황이다. 각 줄의 test는 해당 Task에 넣었다.

1. **따옴표와 backslash가 든 값**(`O'Brien`, `C:\temp\n`, 줄바꿈, 한글): Apply 뒤 다시 읽은 값이 입력과 글자 하나까지 같다 → Task 5 `literals_escape_quotes_and_backslashes`, Task 4 `e_string_values_round_trip`.
2. **SELECT와 Apply 사이에 행이 지워졌거나 PK가 바뀜**: 아무것도 반영되지 않고 어느 행인지 알린다 → Task 4 `missing_row_rolls_back_everything`, Task 7 `not_found_keeps_the_changes_and_names_the_row`.
3. **수 열의 정렬**(`9`와 `10`, 음수, `2^53`보다 큰 bigint, `NaN`, NULL): 값 크기 순이다 → Task 8 `numbers_sort_by_value`.
4. **CSV의 쉼표, 따옴표, 줄바꿈, NULL과 빈 문자열**: 다른 도구가 같은 값으로 읽는다 → Task 9 `csv_quotes_like_copy`.
5. **설정 파일의 단축키 충돌과 menu 키**(`save = "Cmd+Enter"`, `run = "Cmd+Q"`): 조용히 한쪽이 죽지 않고 이유를 보인다 → Task 10 `conflicting_shortcuts_are_an_error`, `menu_keys_are_an_error`.
